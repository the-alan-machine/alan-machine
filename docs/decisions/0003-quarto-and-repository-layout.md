# 0003. Quarto and the repository layout

- Date: 2026-10-04
- Status: accepted

## Context

The book needs plain-text sources that are easy to review in pull requests, mathematics,
citations, cross-references, figures generated by code, and HTML and PDF editions.

## Decision

- The book is a **Quarto** book project. Sources are Markdown (`.qmd`), math is LaTeX, citations
  come from a single `references.bib`, and one source renders to HTML and PDF.
- **One folder per chapter**, `chapters/<slug>/index.qmd`, with the chapter's figures next to it.
- **No numbers in file names.** The order of the chapters lives only in `_quarto.yml`, and Quarto
  numbers them. Cross-references use labels (`@sec-landauer`), never numbers.
- **`freeze: auto`**, with `_freeze/` committed, so code cells run only when their chapter changes
  and a contributor fixing a typo does not need the Python environment.
- `_quarto.yml` lists exactly what is rendered, so repository files such as this one never end up
  in the book.

## Alternatives

- mdBook: simple, but weak on citations.
- Plain LaTeX: excellent output, but a high barrier for contributors.
- Jupyter Book: the closest alternative. Quarto was chosen for its native citations and
  cross-references in plain Markdown.

## Consequences

- Reordering chapters is a one-line change in `_quarto.yml` and does not break links. The Stacks
  Project, a collaborative open mathematics book, keeps permanent tags for its results for the same
  reason: references must survive reorganization.
- A new chapter or paper must be added to `_quarto.yml`.
